구글이 2026년 11월 11일 **Gemini Decisions API**와 이를 구동하는 새 모델 **Gemini Decision 1**(`gemini-decision-1`)을 공개했습니다.

이 블로그를 꾸준히 보신 분이라면 익숙한 이야기일 겁니다. 지난 9월 [TypeSafe의 Jev 포스팅](/blog/typesafe-ai-jev-system-one)에서 정리한 **"텍스트를 생성하지 않고 타입이 정해진 결정을 반환하는 모델"**, 바로 그 범주입니다.

차이가 있다면 그때는 스타트업 하나의 실험처럼 보였는데, **지금은 구글·OpenAI·TypeSafe가 같은 시장에서 붙고 있다**는 것입니다.

<br/>

## 무엇을 하는 API인가

핵심은 간단합니다. **답변을 토큰 단위로 생성하지 않습니다.** 대신 미리 정해둔 선택지들을 **단일 순전파(single forward pass)로 채점**해 확률과 신뢰도를 돌려줍니다.

![Gemini Decisions API 동작 구조](/images/blog/2026-11-13-gemini-decisions-api_architecture.webp)

*이미지 출처: [Google 공식 블로그](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)*

구조를 보면 입력과 질문이 분리되어 있습니다. **하나의 공유 입력**에 텍스트·이미지·오디오·비디오·PDF를 함께 넣고, 그에 대해 **독립적인 질문 여러 개**를 던지면 각각 보정된 답이 나옵니다.

맨 위 hero 이미지가 공식 예시인데, 주방 조리대 사진 한 장을 넣고 세 가지를 동시에 묻습니다. "얼룩이 있는가"(0.95), "어떤 조치를 할까"(wipe_with_cloth, 98%), "심각도는"(1.19/2). 사진 한 장에 판단 세 개가 한 번에 붙는 구조입니다.

### 질문 타입 3가지

| 타입 | 용도 | 반환값 |
|---|---|---|
| **noul** | 예/아니오 조건이 성립할 확률 | 0~1 확률 |
| **choice** | 선택지 2~255개 중 하나 | 우승 선택지 + 전체 정규화 확률 |
| **score** | 0부터 시작하는 순서형 루브릭 | 가중 연속 점수 + 등급별 확률 |

여기서 눈이 번쩍 뜨이는 분이 있을 겁니다. **타입 이름이 Jev와 글자 하나까지 똑같습니다.** `noul`, `choice`, `score`. Jev가 9월에 먼저 쓴 명명을 구글이 그대로 따라간 셈인데, 이 범주의 어휘가 벌써 표준처럼 굳어지고 있다는 신호로 읽힙니다.

모든 답변에는 **0~1 신뢰도 점수**가 붙습니다. 애매한 건만 골라 상위 모델이나 사람 검토자에게 넘기는 라우팅에 쓰라는 용도입니다.

<br/>

## 속도와 한도

| 항목 | 수치 |
|---|---|
| 종단 간 지연 | **150~250ms** |
| 모델 연산 중앙값 | 50~100ms |
| 요청당 질문 수 | 1~**1,000개** |
| 컨텍스트 | 262,144 토큰 (공유 입력 + 전체 질문) |
| 입력 형식 | 텍스트, 이미지, 오디오, 비디오, PDF |

가장 인상적인 주장은 **질문을 1개에서 100개로 늘려도 지연이 거의 평탄하다**는 것입니다. 질문마다 왕복하는 구조가 아니라 한 번의 순전파에서 병렬로 채점하기 때문입니다.

다만 **이 지연 수치는 최대 16K 토큰 컨텍스트 기준**입니다. 입력 한도가 262K인 점을 생각하면, 큰 입력에서의 실제 성능은 공개 수치만으로는 알 수 없습니다.

<br/>

## 가격: 출력이 무료라는 것의 의미

| 항목 | 가격 |
|---|---|
| 입력 | **100만 토큰당 $0.10** |
| 출력 | **$0** |

출력 토큰, 가변 사고(thinking) 토큰, 별도 오디오 전사·OCR 비용이 전부 없습니다. AI Studio에는 프로토타이핑용 무료 티어도 있습니다.

더 중요한 건 과금 단위입니다. **공유 입력은 질문이 몇 개든 요청당 한 번만 과금**되고, 질문마다 자기 지시문과 기준 토큰만 추가됩니다. 이 설계가 비용에 어떤 차이를 만드는지는 구글이 든 예시가 잘 보여줍니다.

![질문을 나눠 보낼 때와 묶어 보낼 때의 비용 차이](/images/blog/2026-11-13-gemini-decisions-api_batching.svg)

4,000토큰짜리 레코드에 검사 20개를 돌릴 때, 요청 20개로 나누면 **1,000건당 약 $8.10**이지만 한 요청에 질문 20개를 묶으면 **약 $0.50**입니다. 같은 일인데 16배 차이가 납니다.

구글은 자사 벤치마크 기준으로 **Gemini 3.5 Flash-Lite + Interactions API 조합보다 약 5배 저렴**하다고 밝혔습니다.

<br/>

## 코드

`google-genai` SDK로 `v1beta`를 지정해 호출합니다. 입력 `input` 필드는 Interactions API와 같은 Content 블록 형식입니다.

```python
from google import genai

client = genai.Client(http_options={"api_version": "v1beta"})

result = client.decisions.create(
    model="gemini-decision-1",
    input=[
        {"type": "image", "uri": "<이미지 URL>", "mime_type": "image/jpeg"},
        {"type": "text", "text": "회의 전 탕비실 조리대 점검"},
    ],
    questions={
        "has_spill": {
            "type": "noul",
            "instructions": "조리대에 닦지 않은 액체 얼룩이 있는가?",
        },
        "next_action": {
            "type": "choice",
            "instructions": "장면에 맞는 정리 조치는?",
            "criteria": {
                "wipe_with_cloth": "작은 얼룩이고 천이 가까이 있음",
                "dispatch_janitorial": "큰 바닥 위험 또는 누수",
                "ready_for_meeting": "깨끗해서 회의 준비 완료",
            },
        },
        "severity": {
            "type": "score",
            "instructions": "조리대 상태의 심각도를 평가하라",
            "criteria": ["깨끗함", "경미한 국소 얼룩", "심각한 얼룩 또는 안전 위험"],
        },
    },
)
```

REST와 JavaScript 가이드도 함께 제공되며, 데모 앱으로 Doorstep Parcels, Speed Sketch, Find the Zoo Keeper가 공개됐습니다.

## 구글이 자사 제품에 이미 쓰고 있다

발표에서 가장 설득력 있는 부분입니다.

- **Gemini Notebook**: 실시간 라우터로 사용. 질의 의도를 밀리초 단위로 분류해 적합한 모델 등급과 사고 수준으로 보내며, 일상 질의 지연을 **최대 40% 단축**
- **Stitch**: rapid canvas 실험에서 제품 흐름을 몇 초 만에 와이어프레임으로 변환, 음성·탭 편집을 거의 즉시 반영
- **CC (Google Labs)**: **200개 이상**의 이모지 중 적절한 반응을 지연 없이 선택
- **Google 검색**: MCP 도구에 대한 적대적 행동·콘텐츠를 탐지하는 **안전 계층**

특히 Gemini Notebook의 라우터 사례는 [Jev 포스팅](/blog/typesafe-ai-jev-system-one)에서 정리한 "모델 라우팅" 패턴과 정확히 같습니다. 싼 판단 모델이 앞단에서 분류하고, 무거운 모델은 필요할 때만 부르는 구조입니다.

## 결정 모델 3파전

이제 이 시장에 큰 이름 셋이 모였습니다.

| 항목 | **Gemini Decision 1** | OpenAI Decisions API | TypeSafe Jev |
|---|---|---|---|
| 공개 | 2026년 11월 11일 | 2026년 10월 | 2026년 9월 중순 |
| 입력 가격 (100만 토큰) | $0.10 | $0.10 | **$0.042** |
| 출력 | 무료 | 무료 | 무료 |
| 요청당 질문 | **최대 1,000개** | 최대 400개 | 상한 없음(컨텍스트 제한) |
| 컨텍스트 | 262,144 토큰 | **1,050,000 토큰** | 64K(옵트인 시 262K) |
| 입력 형식 | **텍스트·이미지·오디오·비디오·PDF** | 텍스트·인라인 이미지 | 텍스트 |

항목별로 1등이 갈립니다. **토큰 단가는 Jev, 컨텍스트는 OpenAI, 질문 수와 입력 형식은 구글**이 앞섭니다.

구글의 차별점은 명확합니다. **멀티모달입니다.** 통화 녹음과 계정 메타데이터를 함께 넣거나, 스캔한 PDF와 손상 사진을 같이 넣고 판단을 받을 수 있습니다. 텍스트만 받는 Jev나 텍스트+이미지인 OpenAI와는 다룰 수 있는 작업의 범위가 다릅니다.

SiliconANGLE에 따르면 선두는 여전히 Jev입니다. 9월 중순 출시 후 며칠 만에 사용자 100만 명을 모았고, 3주 뒤 **75억 달러 가치로 8.7억 달러를 유치**했습니다. 불과 두 달 만에 구글과 OpenAI가 같은 형태의 제품을 들고 따라 들어온 셈입니다.

## 짚어둘 점

발표 수치를 그대로 받기 전에 확인할 부분들입니다.

- **성능 주장이 전부 자체 측정입니다.** "9개 벤치마크 중 7개 우위", "5배 저렴", "가장 낮은 보정 오차" 모두 구글 발표 기준이고, **어떤 벤치마크인지·평가 방법이 무엇인지는 공개되지 않았습니다.** 정확도 수치도 함께 제시되지 않았습니다
- **지연 수치의 조건**: 150~250ms는 16K 토큰 이하 기준입니다. 262K 입력에서의 성능은 알 수 없습니다
- **신뢰도 보정은 검증 대상입니다.** 신뢰도 점수로 라우팅을 설계한다면, 그 점수가 실제로 잘 보정됐는지는 **자기 데이터로 직접 측정**해야 합니다. [Jev 때 독립 평가에서 분포 외 데이터의 캘리브레이션 오차가 기준의 4.4배로 나온 사례](/blog/typesafe-ai-jev-system-one)가 있습니다
- **미지원 기능**: 컨텍스트 캐싱, Batch API, Flex·Priority 추론이 현재 지원되지 않습니다. 대량 배치 처리를 염두에 뒀다면 확인이 필요합니다
- **v1beta 단계**입니다. Google Cloud의 Gemini 지원은 "곧 제공 예정"이고 대기 신청을 받고 있습니다

- **Gemini API**(Gemini Developer API v1beta)와 **Google AI Studio**
- **생태계 연동**: OpenRouter, LangChain, Vercel, LiteLLM, Pydantic AI, Pipecat, LiveKit, OpenCode, `google-genai` SDK
- **Google Cloud의 Gemini**: 곧 제공 예정(대기 등록)

## 정리

1. **정체**: 텍스트를 생성하지 않고 선택지를 채점해 확률과 신뢰도를 반환하는 판단 전용 모델
2. **구조**: 공유 입력 하나에 독립 질문 최대 1,000개, 단일 순전파로 병렬 채점
3. **타입**: noul(예/아니오) · choice(2~255지선다) · score(순서형 루브릭) — Jev와 같은 명명
4. **속도**: 종단 간 150~250ms, 질문 1→100개에도 지연 평탄 (단, 16K 토큰 기준)
5. **가격**: 입력 $0.10/1M, 출력 무료. 공유 입력은 요청당 1회 과금이라 묶을수록 유리
6. **차별점**: 오디오·비디오·PDF까지 받는 **멀티모달**이 경쟁 제품 대비 가장 큰 강점
7. **유의**: 벤치마크·보정 주장이 모두 자체 측정, 캐싱·배치 미지원, v1beta 단계

두 달 전만 해도 신생 스타트업의 실험이었던 범주에 구글과 OpenAI가 나란히 들어왔습니다. **"AI에게 답을 쓰게 할 것인가, 고르게 할 것인가"** 라는 선택지가 이제 셋 중 어느 쪽을 골라도 되는 수준으로 자리 잡은 셈입니다.
