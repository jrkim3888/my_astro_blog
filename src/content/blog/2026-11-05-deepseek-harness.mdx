지난 [딥시크 슈퍼 에이전트 포스팅](/blog/deepseek-super-agent)에서 "슈퍼 에이전트는 DeepSeek Harness 위에서 돌아가는 번들"이라고 짚고 넘어갔습니다. 그 기반이 되는 **DeepSeek Harness** 자체를 이번에 따로 정리합니다.

한 줄로 요약하면 이렇습니다. **모델도, 도구도, 심지어 에이전트 루프와 UI까지 전부 갈아 끼울 수 있는 오픈소스 에이전트 실행 환경**입니다.

<br/>

## 어떤 프로젝트인가

딥시크가 2026년 8월 13일 플래그십 모델 **DeepSeek-V4-Pro** 정식 버전과 함께 공개했습니다. 저장소 이름은 `deepseek-harness`, 명령어는 `dsh`입니다.

| 항목 | 내용 |
|---|---|
| 저장소 | [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) |
| 공개일 | 2026년 8월 13일 |
| 라이선스 | MIT |
| 현재 버전 | v0.2.2-rc.1 (2026년 11월 4일) |
| 스타 / 포크 | 272,509 / 33,184 |
| 기반 프레임워크 | [Cordis](https://github.com/cordiverse/cordis) |
| 상태 | **개발자 프리뷰** |

![DeepSeek Harness GitHub 저장소 화면](/images/blog/2026-11-05-deepseek-harness_repo.webp)

공개 당일 기사에 실린 스타 수가 2만 7,500개였는데, 약 3개월 만에 27만 개를 넘겼습니다. **10배 가까이 늘어난 셈**입니다.

주목할 점은 함께 공개된 V4-Pro가 아니라 하네스 쪽이 더 큰 반응을 얻었다는 것입니다. 당시 V4-Pro는 Artificial Analysis 지능 지수 53점으로 경쟁 모델에 뒤처졌고, Vals AI 평가에서 12위에 그쳤으며, 장시간 코딩에서 중간에 멈추는 문제도 지적받았습니다. 모델은 기대 이하였지만 **실행 환경은 평가가 달랐습니다.**

<br/>

## 핵심 철학: "Everything is a Plugin"

저장소 설명 한 줄이 그대로 `DeepSeek Harness: Everything is a Plugin.`입니다. 말 그대로입니다.

보통의 코딩 에이전트는 모델과 도구, 실행 방식이 제품 안에 고정되어 있습니다. 하네스는 **교체 지점(swap point)** 을 정의해두고, 각 지점마다 여러 구현체 중 하나를 설정 파일에서 고르는 방식입니다.

![교체 지점마다 구현을 골라 끼우는 구조](/images/blog/2026-11-05-deepseek-harness_swap-points.svg)

| 교체 지점 | 선택 가능한 구현 예시 |
|---|---|
| 세션 저장 | JSONL, SQLite |
| 서브프로세스 | 로컬 실행기, E2B 샌드박스 실행기 |
| 셸 | bash, 샌드박스 bash, PowerShell |
| 하위 에이전트 | Claude Code, Codex, ACP 등 6종 |
| 모델 어댑터 | 제공자별 어댑터 |
| 에이전트 루프 | 루프 자체도 플러그인 |

실제로 저장소의 `packages` 디렉터리에는 **53개의 패키지**가 들어 있습니다. 샌드박스, 브라우저 사용, 컴퓨터 사용, MCP, LSP, 스케줄, 텔레메트리, 압축(compaction), 팀, 워크플로까지 기능 단위로 쪼개져 있습니다.

![packages 디렉터리의 플러그인 패키지 목록](/images/blog/2026-11-05-deepseek-harness_packages.webp)

이 구조의 기반은 **Cordis**라는 플러그인 메타 프레임워크입니다. 딥시크가 만든 것이 아니라 외부 오픈소스를 가져와 패치해 쓰는 형태이고, 설계 배경은 *A Programming Paradigm for Spatiotemporal Composability* 논문에 정리되어 있습니다.

여러 플러그인 묶음에 패치 레이어를 순서대로 쌓은 것을 **프로파일(profile)** 이라 부르며, `--dump-config`로 최종 합성 결과를 출력해 확인할 수 있습니다.

<br/>

## Claude Code·Codex와 경쟁하는 게 아니라 끌어다 쓴다

가장 흥미로운 부분입니다. 하네스는 Claude Code와 Codex를 **대체 대상이 아니라 연동 대상**으로 다룹니다.

`packages/subagent` 아래에는 실제로 다음 제공자들이 들어 있습니다.

- `subagent-claude-code`
- `subagent-codex`
- `subagent-acp`
- `subagent-dsh-sdk`
- `subagent-fork-in-process`
- `subagent-spawn-in-process`

특정 작업만 Claude Code나 Codex에 위임하고 결과를 받아올 수 있다는 뜻입니다. 각 패키지는 자체 SDK/CLI를 고정해 번들하므로 PATH의 바이너리에 의존하지 않고, 인증은 각 제품의 기존 로그인을 그대로 씁니다.

호환성도 챙깁니다. 기존 `hooks.json`을 실행하는 브리지(`hooks-claude-code`, `hooks-codex`)가 있고, **`AGENTS.md`와 `CLAUDE.md`를 읽으며**, MCP 클라이언트 역할도 합니다. 이미 Claude Code를 쓰고 있다면 설정 자산을 상당 부분 가져올 수 있습니다.

다만 알아둘 제약이 있습니다. 위임된 에이전트는 **부모 세션의 문맥을 상속하지 않습니다**(`inheritsParentContext: false`). 작업 텍스트에 필요한 정보를 전부 담아야 하고, 세션이 길어질수록 문맥을 다시 보내는 비용이 쌓입니다.

위임 시 권한 모드는 `dontAsk`, `acceptEdits`, `auto`, `bypassPermissions`, `plan` 중에서 고릅니다. `plan` 모드는 계획만 돌려주고 실행을 막습니다.

<br/>

## Code Mode(PTC) — 도구를 하나씩 부르지 않는다

일반적인 에이전트는 도구를 호출할 때마다 모델과 왕복합니다. 파일을 읽고, 결과를 모델에 넘기고, 다음 명령을 받고, 또 실행하는 식입니다. 단계가 많아질수록 왕복 비용이 커집니다.

하네스의 **PTC(Code Mode)** 는 여러 단계를 묶은 **TypeScript 프로그램 하나**를 모델이 작성하게 하고, 그 프로그램을 호스트가 제공하는 비동기 함수에 대해 실행합니다.

![일반 도구 호출과 PTC(Code Mode) 비교](/images/blog/2026-11-05-deepseek-harness_code-mode.svg)

`packages/ptc-runtime` 문서에 따르면 Node가 설정된 파일 정책 아래에서 비동기 함수 본문, REPL 구문, VM Script를 평가합니다. 비동기 함수 본문은 매번 새 프로세스를 쓰고, REPL 모드는 상태 소유자당 프로세스 하나를 유지합니다. 실험적으로 **파이썬 백엔드**도 지원합니다.

<br/>

## 관찰성 — 실행 과정을 전부 들여다본다

세션 기록이 **추가만 가능한 로그(append-only)** 로 남고, 이를 소스별로 보여주는 **trajectory view**가 있습니다. 정리된 채팅 화면이 아니라 원본 문맥을 직접 검사할 수 있다는 점이 다릅니다.

한 리뷰에서는 하나의 작업에 대해 39단계, 도구 호출 44회, 6분 23초, 비용 약 3센트 같은 실행 지표가 그대로 확인됐습니다. 에이전트가 "왜 그렇게 했는지"를 추적해야 하는 상황에서는 이 투명성이 실질적인 차이를 만듭니다.

<br/>

## 크리에이터 모드 — 프롬프트로 플러그인을 만든다

11월 2일 딥시크가 시연한 기능입니다. 텍스트 프롬프트를 넣으면 **AI가 새 플러그인을 직접 만들어 줍니다.** "모든 것이 플러그인"이라는 구조를 대화형으로 확장한 셈입니다.

공개된 생성 사례는 디지털 스티커 메모 벽, 포스터 디자인 도구, 마인크래프트풍 게임, 영상 편집기, 3D 시각화, 논문 리더, 대화 통계 대시보드 등입니다.

갑자기 나온 기능은 아닙니다. 9월 릴리스 노트에 처음 등장했고, 9월 v0.1.6-alpha.2에서 플러그인 관리자를 통한 영구 설치와 실시간 활성화·비활성화가 가능해졌으며, 10월 v0.2.1-alpha.1에서 "Let Agent create a plugin" 항목이 추가됐습니다.

다만 딥시크 스스로 **시연 결과 중 일부는 여러 차례 대화를 거쳐 다듬은 것**이라고 밝혔습니다. 프롬프트 한 번으로 영상과 같은 결과가 나오지는 않습니다.

<br/>

## 설치와 실행

Node.js만 있으면 바로 띄울 수 있습니다.

```
npx @deepseek-ai/dsh web
```

기본적으로 `http://127.0.0.1:3080`에서 웹 UI가 열리고 브라우저가 자동 실행됩니다. 브라우저를 띄우지 않으려면 `--no-open`을 붙입니다. SSH로 실행하면 호스트 URL만 출력됩니다.

소스에서 직접 빌드하려면 다음과 같습니다.

```
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```

기본 기능은 저장소 분석, 파일 수정, 셸 명령 실행, 파일·웹 검색, 작업 계획 수립, 스킬 호출, 하위 에이전트 위임입니다. 민감한 작업에는 승인 정책을 걸 수 있습니다.

모델은 딥시크 전용이 아닙니다. **모델 중립적**이라 OpenRouter를 비롯한 외부 제공자를 API 키로 연결할 수 있습니다.

## 도입 전에 반드시 읽어야 할 보안 공지

이 부분은 가볍게 넘기면 안 됩니다. 저장소에 `SAFETY.md`가 따로 있고, 내용이 상당히 단호합니다.

> **"실험적인 개발자 프리뷰 소프트웨어이며, 보안 감사를 받지 않았고, 안전하거나 프로덕션 준비가 된 것으로 취급해서는 안 된다."**

구체적으로 명시된 위험은 이렇습니다.

- 모델이 생성한 코드와 명령을 실행하고, 서드파티 플러그인을 불러오며, 네트워크·프로세스·자격증명·파일에 접근합니다
- 잘못된 모델 출력, 결함, 설정 오류, 악의적 입력, 신뢰할 수 없는 플러그인은 **호스트 손상, 파일 수정·삭제, 데이터나 자격증명 유출**로 이어질 수 있습니다
- **샌드박스·승인 프롬프트·권한 제어는 위험을 줄일 뿐 격리를 보장하지 않습니다.** 제약이 올바르게 적용되더라도, 프로젝트가 접근할 수 있도록 허용된 자원은 보호하지 못합니다

문서가 권고하는 운영 방식도 그대로 옮기면 다음과 같습니다.

1. 필요한 **최소 권한과 접근**으로 실행할 것
2. **일회용 가상머신, 컨테이너, 전용 환경**을 우선 고려할 것
3. 프로젝트가 접근 가능한 파일은 **백업**해둘 것
4. 위험을 감수할 수 있는 경우가 아니면 민감한 자격증명·데이터를 노출하지 말 것
5. 플러그인·설정·실행하려는 명령을 **먼저 검토**할 것

여기에 더해 **"호환성을 깨는 변경이 있을 것(THERE WILL BE COMPATIBILITY-BREAKING CHANGES)"** 이라고 README에 대문자로 적혀 있습니다. 실제로 8월 공개 이후 v0.1 → v0.2로 올라오며 플러그인 설치 방식과 핵심 API가 바뀌었습니다.

<br/>

## 실사용에서 걸리는 부분들

독립 리뷰에서 지적된 실무적 문제들입니다.

- **추론 모델 설정**: 엔드포인트에 맞게 compat 설정을 수동으로 고쳐야 합니다
- **API 키 읽는 위치**: `apiKeyEnv`는 dsh를 실행한 **프로세스의 환경 변수**에서 읽습니다. 환경이 어긋나면 키가 멀쩡해도 실패합니다
- **Workspace Write 모드**: 쓰기만 제한하고 **읽기는 제한하지 않습니다**
- **첫 실행**: 진행 표시가 없어 멈춘 것처럼 보일 수 있습니다
- **위임 비용**: 매번 새로 시작하므로 문맥을 다시 설명해야 하고, 세션이 길수록 비용이 커집니다
- **명령어 충돌**: 리눅스의 기존 `dsh` 명령과 이름이 겹칩니다

<br/>

## 그래서 누구에게 맞나

Claude Code나 Codex의 대체재로 생각하면 실망할 가능성이 큽니다. 그쪽은 모델·기능·개발자 경험이 통합된 완성형 제품이고, 하네스는 **직접 조립하는 기반**에 가깝습니다.

| 이런 경우 | 적합도 |
|---|---|
| 에이전트 구조 자체를 이해하고 수정하고 싶다 | ◎ |
| 단계별로 모델을 바꿔가며 비용을 최적화하고 싶다 | ◎ |
| 실행 과정을 전부 추적·감사해야 한다 | ◎ |
| 특정 작업만 Claude Code·Codex에 위임하고 싶다 | ○ |
| 설치하고 바로 안정적으로 쓰고 싶다 | ✕ |
| 프로덕션 환경에 바로 투입하려 한다 | ✕ |

[앞서 정리한 슈퍼 에이전트](/blog/deepseek-super-agent)처럼 하네스 위에 올라가는 번들이 나오고 있다는 점도 눈여겨볼 만합니다. 하네스는 그 자체로 완성된 도구라기보다, **다른 에이전트 시스템을 올릴 수 있는 바닥**으로 설계됐습니다.

[지난 10월 GitHub TOP 10](/blog/github-top10-october)에서 정리했듯, 최근 오픈소스의 관심사는 "AI가 코드를 잘 쓰는가"에서 "AI가 만든 결과를 어떻게 다듬고 검증하는가"로 옮겨가고 있습니다. 하네스는 거기서 한 걸음 더 들어가 **에이전트가 돌아가는 바닥 자체를 열어젖힌 쪽**입니다.

<br/>

## 정리

1. **정체**: 모델·도구·루프·UI까지 전부 교체 가능한 오픈소스 에이전트 하네스, MIT 라이선스
2. **규모**: 8월 13일 공개 후 약 3개월 만에 스타 27만 개(공개 당일 2만 7,500개)
3. **구조**: Cordis 기반, 53개 패키지로 기능이 쪼개진 플러그인 아키텍처
4. **연동**: Claude Code·Codex를 하위 에이전트로 위임, `hooks.json`·`CLAUDE.md`·`AGENTS.md` 호환
5. **차별점**: PTC(Code Mode)로 여러 단계를 한 프로그램으로 실행, append-only 로그로 전 과정 추적
6. **신기능**: 크리에이터 모드로 프롬프트에서 플러그인 생성(단, 여러 턴 다듬기 필요)
7. **주의**: **보안 감사를 받지 않은 개발자 프리뷰**, 격리 보장 없음, 호환성 깨는 변경 예고됨

보안 공지의 권고대로 **일회용 VM이나 컨테이너에서, 최소 권한으로, 백업을 둔 상태로** 시작하는 것이 안전합니다. 테스트 목적이라면 운영 자격증명이 들어 있는 환경은 피하는 편이 좋습니다.
